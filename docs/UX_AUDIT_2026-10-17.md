# UX/navigation code audit — 2026-10-17

**Scope audited:** application shell, desktop rail, mobile bottom navigation, global search/command palette, quick-action routing, and the patient/visit/billing/lab destination flows. This is a code-backed functional audit, not a screenshot-based visual audit.

## Findings and fixes

1. **Quick actions were not consumed by their destinations.** The palette/mobile FAB wrote session-storage flags, but no route called `consumeQuickAction`; the action navigated to the list without opening the intended create dialog. PR #62 adds a one-shot listener that handles both navigation to an unmounted route and actions fired while the destination route is already mounted.
2. **Action visibility checked only route-read permission.** A user could see a “new” action without the corresponding create permission. Quick actions now require both route-read and create permission; route handlers recheck create permission before opening the dialog.
3. **New lab order targeted the lab queue list.** That route has no new-order dialog; the app's existing localized hint says lab orders must originate inside an active visit. The shortcut now opens the visits list and displays that hint instead of pretending an order can be created from the queue.
4. **Desktop quick actions were less discoverable than mobile.** PR #62 adds a compact, role-aware desktop quick-action menu in the application header while retaining the mobile FAB and command palette.
5. **Create flows reset stale draft state when opened by shortcut.** Patient, visit, and invoice shortcuts reset their draft state before opening, preventing a previous incomplete draft from silently reappearing.
